Deliverable 7 — Shared Payload Library & Common Schemas

This is one of the most overlooked parts of AI platforms, but it's something every mature engineering team does.

Why do we need it?

Currently, every workflow defines its own JSON.

For example:

Conversation Manager sends

{
  "borrower_id": "...",
  "application_id": "..."
}

Document Intake sends

{
  "applicationId": "...",
  "borrower": "...",
  "loanId": "..."
}

OCR Agent sends something else.

After 10 agents, you'll have 10 different payload formats.

That becomes a maintenance nightmare.

Instead, we create one shared payload library.

Every workflow imports and uses the same objects.

Schema 1 — Borrower

Every workflow receives the exact same Borrower object.

{
  "borrower": {
    "id": "",
    "first_name": "",
    "last_name": "",
    "email": "",
    "phone": "",
    "broker_id": ""
  }
}

Maps directly to your borrowers table.

Schema 9 — Standard Response

Every workflow returns the same envelope.

{
  "status": "SUCCESS",

  "contract_version": "1.0",

  "workflow": "",

  "execution_id": "",

  "payload": {},

  "error": null
}

Or, on failure:

{
  "status": "FAILED",

  "contract_version": "1.0",

  "workflow": "",

  "execution_id": "",

  "payload": null,

  "error": {
    "code": "",
    "message": "",
    "retryable": false
  }
}

This means every parent workflow can process child workflow responses consistently.

Naming Standards

To avoid inconsistency, adopt these conventions from day one:

JSON keys: snake_case
UUID fields: <entity>_id
Timestamps: ISO-8601 UTC
Enum values: UPPER_SNAKE_CASE
Boolean fields: is_..., has_..., requires_...

Example:

{
  "document_id": "...",
  "is_password_protected": true,
  "requires_human_review": false
}
Engineering Recommendation

This is where I'd make one important improvement to the overall architecture.

Rather than storing these schemas only as documentation, create a Shared Contracts folder in your repository:

shared/

    contracts/
        contract_v1.md

    schemas/
        borrower.schema.json
        broker.schema.json
        application.schema.json
        attachment.schema.json
        document.schema.json
        conversation.schema.json
        workflow.schema.json
        execution.schema.json
        response.schema.json

    enums/
        application_status.md
        document_status.md
        workflow_status.md

Then every AI agent and every n8n workflow references these shared definitions instead of redefining payloads. When you need to add a field—such as preferred_contact_method to the Borrower schema—you update it once and every workflow can adopt the new version in a controlled way.
